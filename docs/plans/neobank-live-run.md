# Suwappu Bank live run (local PostgreSQL + forked Base)

## What is real vs local

- Real: api-ts server booted from source (`bun run src/index.ts`) against local PostgreSQL 16 (`suwappu_drizzle_first`, port 5433), migrations applied with `drizzle-kit migrate` (0034 included; journal at id 35). All HTTP calls go through the real Hono routes (`/webapp/bank/*`, `/v1/agent/bank/*`) with real auth middleware, no bypass flags.
- Auth: webapp requests carry `X-Telegram-Init-Data` signed by `lib.ts` with a throwaway `TELEGRAM_BOT_TOKEN` exactly as `TelegramAuthService` verifies it (HMAC WebAppData, 5 min max age, fresh per request). Agent via real `POST /v1/agent/register` (bearer `suwappu_sk_*`).
- Local: chain is a Hardhat 2 node forking Base mainnet (chainId 8453, RPC `https://mainnet.base.org`, reached through the sandbox proxy), listening on :8545 and wired in via `BASE_RPC_URL`. foundry/anvil could not be installed (github.com release download blocked by egress policy, 403), so Hardhat was used instead. The bank asset registry is hardcoded (`services/bank/assets.ts`), so the real Base USDC contract at 0x8335...2913 is used and balances are injected with `hardhat_setStorageAt` (mapping slot 9) plus `hardhat_setBalance` for gas.
- Local: signer. Turnkey has no credentials here, so signing falls through `withSigningFallback` to `PYTHON_API_URL/internal/sign-transaction`. The Python service cannot run here (no fastapi), so `signer.ts` is a stand-in that signs EIP-1559 txs with throwaway keys keyed by `wallets.id`. Wallet rows (users, wallets with `wallet_provider='turnkey'`, fake sub-org id) are inserted directly in SQL because the Python provisioning path is unavailable.
- Setup scripts live in `/tmp/claude-0/-home-user-suwappubot/56f114d7-35df-54d5-b0c2-8208538647f9/scratchpad/live/` (env.sh, lib.ts, signer.ts, hh/).

## Bugs found

1. `insertTransferGuarded` (`api-ts/src/services/bank/BankTransferService.ts` ~L618) documented an available-balance (ledger minus holds) check but never called `assertAvailable` (imported, unused; `consumesHold` param unused). Effect: overdraft returned 200 with a persisted `failed` transfer, and held funds (3f) were not protected. Fix: `if (row) await assertAvailable(from.id, tx, amount, consumesHold)` after the insert, inside the same transaction (`// MONEY-PATH`); replays still return the original row. FIXED.

2. `BankTransferService.transfer` (external branch, ~L744): `toExternal` equal to the source account's own wallet address was accepted (ledger debit, no on-chain movement, permanent reconcile drift). Fix: VALIDATION 400 (`// MONEY-PATH`). FIXED.

3. `BankRemittanceService.ts` (~L206 claim escrow `openAccount`, ~L128 recipient `ensureAccount`): `openAccount` was called without a custody `wallet`, so every claim-link send failed and a first-time recipient could never be auto-opened an account. Fix: claim escrow reuses the sender account's wallet (as BankEscrowService does); recipient account resolves `ledger.resolveCustodyWallet(owner, family)` (`// MONEY-PATH`). FIXED.

4. `routes/bank/business.ts` L34 invite schema omitted `telegramId` (service `createInvite` binds invites to `tg:<id>`; HTTP could only invite by email, requiring users with recoveryEmail). Fix: add optional `telegramId` to the zod schema. FIXED.

5. `BankAgentPayService.ts` ~L93 `requireAgent` used `throw bankErr('FORBIDDEN')` synchronously inside `Effect.gen`, which is a defect: a webapp (non-agent) caller of `/agents/accounts` etc. got HTTP 500 'Unhandled error' instead of 403 FORBIDDEN. Fix: return `Effect.fail(bankErr(...))` / `Effect.void` and `yield*` it at the 5 call sites (`// MONEY-PATH`). FIXED, verified 403 after restart. Other `throw bankErr` lines in the file are inside async/sync helper callbacks that are wrapped (not re-audited).
