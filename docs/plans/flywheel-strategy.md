# The Suwappu Flywheel — Execution · Float · Agents (+ TradFi↔DeFi Arb)

**Status:** Research / strategy capstone · **Date:** 2026-06-25 · **Owner:** TBD
**Unifies:** [`llm-reseller-strategy.md`](./llm-reseller-strategy.md) ·

The first two docs asked "which models / agents." This one answers the real question:
**what's the compounding loop?** The conclusion from all the research: the models are
commodity inputs; the flywheel is a **three-legged loop — Execution, Float, and the
Agent economy — spinning on one hard-to-copy core.**

---

## 0. The flywheel core (name it, or it's just a pitch-deck word)

> **Core = proprietary cross-chain order-flow + intent data, generated by captive
> Telegram / managed-wallet distribution.**

A competitor can fork a router and rent the same Claude/GPT. They **cannot** replay your
historical fill quality across 7+ chains, or your custody-level view of *who trades what,
when, and how well*. Every leg below either **feeds** that dataset or **monetizes** it.
If a proposed feature does neither, it's a distraction.

A flywheel is durable only if each turn deposits something a rival can't replay. Ours:
accumulated fill-quality data + captive distribution + custody switching costs. The
points/XP system is **fuel, not a flywheel** — weight it toward fill quality, retained
volume, and net deposits, not raw tx count (88% of airdropped tokens die <3 months).

## 1. The three-legged loop

```
                  ┌─────────────────────────────────────────────┐
                  │   CORE: proprietary execution + intent data  │
                  │   (captive Telegram + managed wallets)       │
                  └───────────────┬─────────────────────────────┘
            feeds & is fed by     │
        ┌───────────────┬─────────┴────────┬───────────────────┐
        ▼               ▼                   ▼                   │
 ┌────────────┐  ┌──────────────┐   ┌────────────────┐         │
 │ ① EXECUTION│  │ ② FLOAT       │   │ ③ AGENT ECONOMY│         │
 │ swaps/perps│  │ yield on idle │   │ x402-paid MCP  │         │
 │ + B2B SOR  │  │ balances +    │   │ tools + agent  │         │
 │ (bps fees) │  │ Earn/RWA      │   │ marketplace    │         │
 └─────┬──────┘  └──────┬───────┘   └───────┬────────┘         │
       │  volume sits    │ funds              │ each agent call │
       │  in wallets ───▶│ incentives & ─────▶│ routes more ────┘
       │                 │ better agents      │ volume to ①
       └─────────────────┴────────────────────┘
   more volume → more data → better routing/signals/agents → better fills → more users → more volume
```

### ① Execution-as-a-Service — *the money path that already exists*
A bps fee on swap/perp volume, plus the **B2B angle: license the execution backend** so
other apps embed it via the MCP/agent API. This is the loop everything else routes back
into. Precedent take-rates: **Jupiter 10bps (2bps stable), 0x 0–100bps integrator,
1inch 0–30bps + positive-slippage, LI.FI 25bps default (600+ partners, ships inside
Coinbase Wallet & MetaMask).** Jupiter's "more flow → better execution → more flow" got it
~55% of Solana aggregator share. **This is the strongest, most defensible loop we have** —
seeing trade *intent before execution* directly powers copy-trading, alerts, and agent
routing.

### ② Stablecoin float / yield — *the huge, underrated near-term win*
We custody user funds via Turnkey and earn **nothing** on idle balances today. T-bill-rate
yield (~4–5%) on idle balances + transient swap float is high-margin and passive:
- **Coinbase earned $910M (FY2024) purely on USDC reserve interest.** Tether netted
  **$13B (2024), >$10B (2025)** off ~$135B in Treasuries.
- Consumer skin = **"Earn"**: be the in-app front-end for tokenized treasuries (Ondo,
  BUIDL, Franklin BENJI), taking a distribution spread on issuer fees (BENJI 0.15%, BUIDL
  ~0.20–0.50%, OUSG/USDY 0.15–0.65%). Tokenized T-bills crossed **$7B onchain in 2026**.

> ⚠️ **Regulatory line (critical).** *Earning* float as the company is standard
> (Coinbase keeps USDC reserve income). *Paying yield to users* is a different animal —
> the SEC went after BlockFi / Celsius / Coinbase "Lend" for exactly this (unregistered
> securities). Structure as (a) company keeps the float, or (b) distribute a
> *regulated/licensed* yield product (the RWA-distribution path with a licensed issuer),
> never an unregistered "earn X% on your balance." Get counsel before building leg ②.

### ③ Agent economy (x402) — *the strategic, early, uniquely-aligned leg*
Expose execution/wallet tools as a **paid x402 MCP server** + an **agent marketplace**
that takes a cut (Virtuals 1% → Apple 30% spectrum). The loop: more agents call → more
volume to ① → better pricing → more agents → fees fund better first-party agents that
bring users. x402 is real at scale (**~165M tx, ~69k active agents, ~$600M annualized,
zero protocol fee**) — *but* CoinDesk's honest read is **demand "just not there yet"
(Mar 2026)**. Treat as a **strategic option you're early to**, not a 2026 revenue line.
The moat isn't being *an* x402 endpoint (commodity) — it's being the **best-execution**
endpoint, which loops straight back to the core data.

**Where the first two docs fit:** the LiteLLM model proxy and the agent SDKs are the
**plumbing inside leg ③** — they let us run first-party agents and let third-party agents
transact. They are not the product; the execution rails are.

## 2. TradFi↔DeFi arbitrage — a spoke, not the hub

Don't run an arb fund on your own book (regulated, capital-intensive). The durable
product is **arbitrage-as-an-x402-agent**: an agent that finds edges and executes through
*your* rails, billed per-query/per-fill. Ranked by fit to existing infra:

| Strategy | Edge / size | Fit | Verdict |
|---|---|---|---|
| **Funding-rate / basis arb** | Delta-neutral, **~10–30% net APY**; no HFT/colocation (funding pays on 1–8h cycles → speed-of-*data*, not execution) | **Best** — perps infra already exists; add a spot/wallet hedge leg | **#1 build candidate** |
| **Cross-chain non-atomic inventory arb** | ~$869M/yr across 9 chains; less saturated because it carries bridge-latency/inventory risk | **High** — our 7+ chain execution + managed inventory is built to absorb exactly that risk | Strong #2 |
| **Prediction-market maker-side arb** | Polymarket 0% maker vs Kalshi taker fees; automatable, cheap | Medium — fits an x402 agent | Optional agent |
| Atomic CEX-DEX MEV | 3 searchers took ~75% of $233M | — | **Dead for us** (builder-integrated oligopoly) |
| Bulk tokenized-treasury carry | Thin/negative vs current borrow | — | **Dead** (easy version captured) |
| FX / on-off-ramp corridors | Argentina gap now <1% | — | A payments/licensing business, not arb |

> ⚠️ **Managing user capital in any of these is almost certainly a licensed activity**
> (securities / derivatives / money transmission). The agent-that-executes-on-our-rails
> framing keeps us as *infrastructure* (leg ①/③) rather than a fund — that's the line to
> hold.

## 3. The unified flywheel, in one sentence

**Swap/perp execution (①) and copy-trading drive volume → balances sit in wallets earning
float (②) → agents (incl. arbitrage agents) transact through the marketplace on x402 (③),
each call routing more volume back to ① → all of it deposits proprietary execution/intent
data into the core → better routing, signals, and agents → more users → repeat.**

Float and agent fees **fund** the incentives and the first-party agents; execution data is
the **flywheel**; XP is the **fuel** for cold-start.

**Stop positioning as "a reseller of Anthropic/OpenAI."** Position as **the execution &
settlement layer for the crypto agent economy** — sell *actions* (swaps, quotes,
portfolio, arb fills) priced in credits/x402, earn the *float* on balances in flight, and
treat the models as interchangeable wholesale inputs.

## 4. Ranked roadmap

**Tier 1 — flywheel core (build now):**
1. **① Execution take-rate + B2B SOR** — formalize bps fees; expose the execution backend
   via the existing agent API so others embed it. Already your business; make it a
   product. *(reuses `api-ts/src/routes/agent.ts`)*
2. **② Stablecoin float** — the highest-margin passive win; idle Turnkey balances earn
   nothing today. **Gate on legal structuring first** (company-float vs licensed yield).
3. **③ x402-paid MCP tools** — wire x402 pricing onto `quote`/`portfolio` MCP tools so an
   external agent can pay-per-call. Cheap (reuses x402 middleware); plants the agent-economy
   leg early.

**Tier 2 — volume overlays:**
4. **Copy-trading marketplace** — top traders earn a cut (eToro 1.5% of copied assets,
   Hyperliquid 10% profit share); feeds execution volume + Telegram-native. You already
   have copy-trading.
5. **Funding-rate arb agent** — first arbitrage-as-an-agent product on perps infra.

**Tier 3 — strategic / byproduct (later):**
6. RWA "Earn" distribution (licensed wrapper over ②); agent marketplace cut; on-chain
   intelligence/order-flow data products (byproduct of the core data, different GTM).

**Skip:** Claude/GPT fine-tuning (impossible), reselling raw tokens (commodity, ToS-bound),
running an arb fund on own book (regulated), autonomous-trading *product* (commodity +
liability).

## 5. The honest risk register

| Risk | Note |
|---|---|
| **Regulatory (the big one)** | Float-paid-to-users, RWA distribution, and user-capital arb are all **licensed activities**. Company-keeps-float and agent-executes-on-rails are the defensible framings. Counsel-gate Tier 1.2 and Tier 2.5. |
| **Disintermediation** | Users/agents go direct to the DEX/model. Hyperliquid fell ~80%→38% share; dominance isn't permanent. Defense = custody switching cost + best-execution data moat. |
| **Thin / leaky moat** | "Liquidity sticks only when leaving is more painful than staying." A fork-able router + emissions-held users = leaky bucket. The data core is the only durable part. |
| **Agent-economy timing** | x402 demand is real but early ("not there yet"). Build leg ③ as a cheap option, not a 2026 revenue plan. |
| **Incentive farming** | XP/points farmed-and-dumped. Weight toward retained volume + net deposits, not tx count. |
