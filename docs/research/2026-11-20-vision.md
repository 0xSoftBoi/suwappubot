# Suwappu: hands for AI (vision, 2026-11-20)

## The bet

AI assistants are becoming the main way people deal with money. Hundreds of millions of people
already ask Claude, ChatGPT, Gemini and Telegram bots what to do with it. The next step is that
they ask the assistant to **do it**: buy this, move that, pay this agent, rebalance to my rules.

Every assistant will need **hands**: a way to find the best execution, enforce the user's rules,
get a human yes when it matters, prove what happened, and settle. Today those hands are bundled
into walled gardens. Coinbase serves Coinbase wallets, Privy/Stripe serves Stripe merchants, and
Jupiter serves Solana. **No neutral layer works for any assistant, any chain and any wallet while
the user stays in control.**

Suwappu should be that layer. We are not "a DEX bot" and not "an AI company". We are **the money
layer AI runs on**.

## Why us: we already built most of the stack

The audits (`docs/research/2026-11-20-product-competitor-gaps.md`) found the pieces are real.
They just were never assembled into one story or put in front of anyone.

| Layer | What it does | What exists today |
|---|---|---|
| **Route** | Best execution across every venue and chain | 8.3k-LOC router with about 25 providers and oracle-sanity ranking (`bot/services/swap_engine.py`); execution benchmark and shadow calibration (`execution_sync*`) |
| **Guard** | The user's rules, enforced: caps, allowlists, step-up approvals, kill switch | `PolicyService.ts` (fail-closed, org-wide caps), `ApprovalService.ts`, kill switch on `/v1/agent/swap/execute` |
| **Prove** | Every decision is verifiable after the fact | Hash-chained audit with `/audit/verify`, sealed-then-revealed decisions with on-chain anchoring (`lib/seal.ts`, `anchor.ts`), Arbiter's TDX-attested verdicts |
| **Settle** | Agents pay and get paid, with refunds if delivery fails | x402/MPP metering, credits, Arbiter escrow (NEAR testnet, settled end to end) |
| **Reach** | Wherever the user already is | Hosted MCP (23 tools, keyless reads as of today), A2A, Telegram, WhatsApp flows, Discord, terminal, SDKs |

As of today an MCP quote returns a `sign_url` that opens a pre-filled, self-custodial swap. That is
the smallest complete loop: **AI proposes → human approves → wallet signs → chain settles**.

## Three moonshots built on that stack

### 1. The Suwappu Execution Index: an "NBBO for DeFi"
- **What it is:** a public, verifiable scoreboard of who actually gives the best price per pair,
  size and chain. It is built from sealed quotes compared with realized fills, using the
  `execution_sync` shadow machinery we already have.
- **Who uses it:** any agent can query it before routing.
- **Why it matters:** it becomes the reference every assistant checks. That makes us the
  standard, not just one more aggregator. Data compounds, and nobody neutral publishes this.

### 2. Agent Pass: OAuth scopes for money
- **What it is:** one set of spending rules a user defines once, such as "$200/day, only
  blue-chips, ask me above $500, never bridge". Every assistant they use honors it through our
  MCP or API.
- **Where approvals go:** over Telegram, WhatsApp or the wallet.
- **How it's verified:** an attested audit log the user can check.
- **Why it matters:** the user owns the rules, not the AI vendor. This is the trust primitive
  the agent economy is missing. Privy and Turnkey sell it to developers. Nobody gives it to
  **end users**, portable across assistants.

### 3. Pay-on-delivery for agent commerce
- **What it is:** when agents buy from agents (data, compute, work), the money is held and
  released only when an attested check passes.
- **What it builds on:** Arbiter and x402.
- **Why it matters:** this is what turns agent payments from demos into a market.

## The consumer face: an AI money manager in every chat

The same layer, pointed at people rather than developers:
- **Who:** WhatsApp and Telegram users in places where stablecoins beat the local bank.
- **What they say:** "save $10 every Friday", "put idle dollars where they earn".
- **How it runs:** the assistant does it under their Agent Pass rules.
- **What it uses:** BTC-yield and lending rails we already prototyped (Starknet, Morpho, HL
  vaults).
- **Why it's ours:** this is where WhatsApp and Telegram distribution is enormous and
  underserved, and where we already have the surfaces.

## How it compounds

More assistants connected → more routed volume → better Execution Index data → better routing
→ more assistants choose us. Agent Pass adds lock-in that users like: their rules and history
live with us and travel everywhere. Revenue stacks on every layer:
- routing fee in bps;
- the policy and approval tier;
- settlement fee;
- Index data.
